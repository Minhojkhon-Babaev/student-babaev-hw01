# Схема данных

Одна строка — одно почасовое наблюдение погоды в одном городе: `(city_id, observed_at)`.
Суррогатных идентификаторов не добавлялось, ключ естественный.

## Таблица `lakehouse.babaev.weather` (она же Parquet и подготовленный CSV)

Типы задаются явно в `pipeline.py` (`WEATHER_SCHEMA`), `inferSchema` не используется нигде.
Колонка «NULL» — правило решения, а не физическое ограничение файла: CSV не хранит
`NOT NULL`, поэтому обязательность проверяется значениями после чтения.

| Поле | Тип (Spark) | Тип (Trino) | Смысл | NULL |
|---|---|---|---|---|
| `city_id` | `string` | `varchar` | Машинный идентификатор города (slug), задан в `fetch_source.py`; часть ключа | запрещён, строка уходит в reject |
| `city_name` | `string` | `varchar` | Название города по-русски, для чтения человеком | запрещён |
| `country_code` | `string` | `varchar` | Код страны ISO 3166-1 alpha-2 (`RU`, `KZ`, `BY`) | запрещён |
| `latitude` | `double` | `double` | Широта ячейки сетки ERA5 из ответа API (не запрошенная координата города) | запрещён |
| `longitude` | `double` | `double` | Долгота ячейки сетки ERA5 | запрещён |
| `elevation_m` | `double` | `double` | Высота ячейки над уровнем моря, м | запрещён |
| `observed_at` | `timestamp` | `timestamp(6) with time zone` | Начало часа наблюдения в UTC; часть ключа | запрещён |
| `observed_date` | `date` | `date` | Дата наблюдения в UTC; проверяется на согласованность с `observed_at` | запрещён |
| `temperature_2m_c` | `double` | `double` | Температура воздуха на высоте 2 м, °C — основная мера | запрещён (ключевое поле вопроса) |
| `apparent_temperature_c` | `double` | `double` | Ощущаемая температура, °C | допустим |
| `relative_humidity_2m_pct` | `int` | `integer` | Относительная влажность на 2 м, % | допустим |
| `precipitation_mm` | `double` | `double` | Сумма осадков за час, мм | допустим |
| `wind_speed_10m_kmh` | `double` | `double` | Скорость ветра на 10 м, км/ч | допустим |
| `surface_pressure_hpa` | `double` | `double` | Давление на уровне поверхности, гПа | допустим |
| `cloud_cover_pct` | `int` | `integer` | Общая облачность, % | допустим |

Фактически в выгрузке за 2024 год NULL нет ни в одном поле (см. `evidence/spark-result.txt`).

Про `observed_at`: Spark пишет тип `timestamp` (момент времени), Iceberg хранит его как
`timestamptz`, поэтому Trino показывает `timestamp(6) with time zone` и печатает суффикс `UTC`.
Это одно и то же значение, а не расхождение схемы: сессия Spark работает с
`spark.sql.session.timeZone=UTC`, и контрольные агрегаты в обоих движках совпадают.

### Партиционирование

* Parquet: `partitionBy("city_id")` — 14 партиций примерно по 8 784 строки. Город —
  главный ключ группировки в исследовательском вопросе, значений немного и они
  сбалансированы. По `observed_date` партиционировать нельзя: получилось бы 366
  каталогов по 336 строк.
* Iceberg: `PARTITIONED BY (months(observed_at))` — 12 партиций по одному файлу.
  Догрузки приходят диапазонами дат, поэтому скрытое партиционирование по месяцу
  совпадает с порядком поступления данных и не требует отдельной колонки в схеме.
* Уникальный идентификатор в партиционировании не используется.

## Отклонённые строки `s3://datalake/babaev/weather/rejects/`

Схема = схема таблицы выше плюс две колонки:

| Поле | Тип | Смысл |
|---|---|---|
| `_corrupt_record` | `string` | Исходная строка CSV, если её не удалось разобрать по схеме |
| `reject_reason` | `string` | Причины отклонения через `; ` — например `нет значения температуры; влажность вне 0..100 %` |

Исходные значения сохраняются целиком, поэтому отклонённую строку можно разобрать вручную.
На текущей выгрузке путь создан и содержит 0 строк.

## Справочник `memory.default.city_reference` (каталог Trino `memory`)

| Поле | Тип | Смысл |
|---|---|---|
| `city_id` | `varchar` | Ключ соединения с таблицей наблюдений, уникален |
| `city_name_ru` | `varchar` | Название города |
| `federal_district` | `varchar` | Федеральный округ РФ |
| `utc_offset_hours` | `integer` | Постоянное смещение времени региона от UTC |

Справочник покрывает только 12 городов РФ из выборки. Астана и Минск в него не входят
намеренно: они вне административного деления РФ и в отчётах попадают в явную группу
«Не сопоставлен».
